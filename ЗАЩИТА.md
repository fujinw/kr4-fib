# Подготовка к защите КР4

Максим Шарифуллин, ЭФБО-01-25. Проект LUMO создан на основе адаптивной версии КР3. Основная тема — работа с данными, DOM, событиями и формами на чистом JavaScript.

## Что показать за несколько минут

1. Откройте `js/data.js`: 10 объектов с одинаковыми полями, числами в `price` и уникальными `id`.
2. Покажите `catalog.card()` и пустой HTML-контейнер `data-catalog-grid`: карточки создаёт JavaScript.
3. Введите `aster`, выберите категорию, сортировку, покажите пустой результат и сброс.
4. Откройте быстрый просмотр и закройте его Escape. Покажите заблокированную покупку Wave.
5. Добавьте два товара, измените количество, примените LUMO10 и перезагрузите корзину.
6. Найдите `reduce` в `cart.js`, объясните `{ id, quantity }` и восстановление из хранилища.
7. Отправьте пустую форму заказа, затем введите корректные данные и дождитесь учебного результата.
8. Покажите Console, README и запуск тестов `node --test tests/core.test.cjs`.

## Ответы на контрольные вопросы

### 1 Что хранится в data.js

Массив `Lumo.products` из 10 товаров и словарь названий категорий. Каждый товар содержит id, название, категорию, числовую цену, наличие, ключ изображения, размер, материал, бейдж и описание. Корзина не хранится в массиве товаров.

### 2 Почему каталог удобно хранить как массив объектов

Объект объединяет свойства одной модели, массив — все модели. `filter` выбирает подходящие товары, `sort` меняет порядок копии, `find` находит товар по id. Одна функция создаёт все карточки из данных.

### 3 Почему у товаров должны быть одинаковые свойства

Одинаковая структура позволяет одинаково отображать и проверять каждую модель. Необязательный бейдж представлен пустой строкой, а не отсутствующим полем. Единые типы предотвращают ошибки расчётов.

### 4 Как работает поиск по названию

Обработчик `input` запускает обновление. `trim()` убирает крайние пробелы, `toLocaleLowerCase()` приводит запрос и название к нижнему регистру, `includes()` проверяет вхождение. Пустая строка подходит всем товарам.

### 5 Как работает фильтрация по категории

`select` содержит значения, совпадающие с `product.category`. В `filter()` проверяется совпадение, а пустая категория означает все типы. Категория объединяется с поиском, материалом, наличием и диапазоном цен через логическое И.

### 6 Как работает сортировка по цене

Для возрастания используется `(a, b) => a.price - b.price`, для убывания — обратная разность. Отрицательный результат ставит `a` раньше `b`. Для названий используется `localeCompare()`.

### 7 Почему sort лучше применять к копии

`sort()` меняет массив, на котором вызван. `[...selected].sort(...)` сохраняет исходный порядок товаров. Поэтому выбор «По умолчанию» возвращает порядок из `data.js`.

### 8 Что такое DOM

Объектное дерево HTML-документа в браузере. JavaScript находит узлы, создаёт новые, меняет текст и атрибуты. Изменение массива само по себе страницу не меняет: функцию отображения нужно вызвать снова.

### 9 Для чего используется querySelector

Возвращает первый элемент по CSS-селектору или `null`, если его нет. Например, `document.querySelector('[data-catalog-grid]')` находит контейнер товаров. Проверка на `null` позволяет подключать общие скрипты на разных страницах.

### 10 Для чего используется createElement

Создаёт новый DOM-элемент, например `document.createElement('article')`. Он ещё не находится на странице. В проекте обёртка `Lumo.el()` создаёт элемент, назначает классы и безопасно заполняет текст.

### 11 Почему используется textContent

`textContent` вставляет строку как текст. Название товара, поисковый запрос и имя пользователя не разбираются как HTML. Даже строка с тегом и обработчиком останется видимым текстом.

### 12 Чем опасен innerHTML

Браузер разбирает строку как HTML. Если включить в неё непроверенные данные, можно создать нежелательные элементы и обработчики, то есть допустить XSS. В приложении `innerHTML` не используется: узлы создаются явно, текст задаётся отдельно.

### 13 Для чего используется classList

Для добавления, удаления и переключения CSS-классов без ручной сборки строки `className`. Например, `field.classList.toggle('is-invalid', Boolean(message))` включает оформление ошибки только при наличии сообщения.

### 14 Для чего нужны атрибуты data

Хранят прикладные метки и значения в HTML. Кнопка `data-add-to-cart="1"` передаёт id товара через `button.dataset.addToCart`. Значения из `dataset` — строки, поэтому id преобразуется в число.

### 15 Что такое событие

Сигнал о действии пользователя или изменении состояния. `click` означает нажатие, `input` — редактирование, `change` — изменение выбранного значения, `submit` — отправку формы. В проекте есть и собственное событие `cart:change` для пересчёта интерфейса.

### 16 Почему обработчики подключены через addEventListener

Поведение остаётся в JS-файлах, HTML описывает структуру. Можно зарегистрировать несколько обработчиков одного события и позднее удалить конкретный. Inline-атрибуты вроде `onclick` не нужны.

### 17 Что такое делегирование событий

Обработчик назначается общему предку, а целевая кнопка определяется через `event.target.closest()`. Событие всплывает от кнопки к предку. Так добавление в корзину работает у карточек, которые были созданы после установки обработчика.

### 18 Для чего используется preventDefault

Отменяет стандартное действие браузера. В обработчике формы это предотвращает навигацию и позволяет проверить поля и вывести результат на текущей странице. Всплытие события этот метод не останавливает.

### 19 Как работает базовая валидация формы

При `submit` каждое поле проверяется функцией `errorFor()`. Проверяются обязательность, имя, e-mail, телефон, согласие и адрес при доставке. Если есть ошибки, показываются подписи и фокусируется первое неверное поле. Если всё верно и корзина заполнена, запускается имитация подготовки заявки.

### 20 Почему сообщения выводятся на страницу

Ошибка остаётся рядом с полем и помогает исправить конкретное значение. `aria-invalid`, `aria-describedby` и область `role="status"` передают состояние вспомогательным технологиям. Всплывающий `alert()` прерывал бы работу и исчезал после закрытия.

### 21 Какие самостоятельные доработки реализованы

Корзина с количеством и удалением, сумма через `reduce`, проверяемое хранение в `localStorage`, промокод, доставка, счётчики, дополнительные фильтры, быстрый просмотр, отдельные страницы моделей, состояния наличия и имитация подготовки заявки. Подробные сценарии и ожидаемые суммы есть в README.

### 22 Почему копирование методички не даёт максимальный балл

По условиям КР базовые паттерны дают до 4 баллов из 8. Остальные критерии относятся к развитию проекта: состоянию, расчётам, сохранению, дополнительным сценариям, понятному коду и документации. На защите нужно объяснить решения и показать их работу; итоговую оценку выставляет преподаватель.

## Как объяснить расчёт и хранение

Для каждой позиции `price * quantity` даёт стоимость. `reduce()` складывает позиции, начиная с нуля. Промокод уменьшает сумму товаров на округлённые 10%. Доставка добавляется после скидки; порог бесплатного курьера тоже проверяется после скидки.

В `localStorage` хранится JSON, поэтому для записи нужен `JSON.stringify()`, а для чтения — `JSON.parse()`. Чтение окружено `try/catch`: JSON может быть повреждён, а хранилище — запрещено. После разбора проверяются id, наличие, повторы и диапазон количества. Цена берётся из каталога, а не из сохранённой записи.

Валидация в браузере не заменяет серверную проверку. В этой работе сервера нет: все товары, адреса шоурума и формы относятся к учебному магазину.
